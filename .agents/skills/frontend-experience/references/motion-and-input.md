# 모션·입력·성능

인터랙션을 구현하거나 실제 화면을 검수할 때 읽는다. 선택한 경험에 해당하는 항목만 적용한다.

## 반복되는 등장과 스크롤

프로세스·에디토리얼 페이지에서는 제목 → 본문 → 이미지 → 항목이 내용 순서대로 나타나게 구성한다. 충분히 화면 밖으로 나간 뒤 돌아오면 다시 등장하는 경험을 기본 후보로 삼는다. 뷰포트 경계에서 반복 초기화되어 깜빡이거나 텍스트를 읽기 전에 사라져서는 안 된다. 화면 밖까지 내려간 전체 페이지 캡처만으로 등장 완료 상태를 검증하지 말고 실제 스크롤 위치별로 확인한다.

스크럽은 진행률과 콘텐츠 변화가 연결되어야 하고 핀은 다음 구간에서 반드시 풀려야 한다. 레이아웃용 transform과 모션용 transform을 분리한다. 폰트·이미지 로딩과 resize 뒤 위치·분할 행·스크롤 거리를 다시 측정한다.

부드러운 스크롤은 현재 문서 또는 별도 스크롤 패널의 실제 root를 사용한다. 라이브러리가 만든 추가 RAF와 ScrollTrigger 갱신을 중복 실행하지 않는다. 앵커의 헤더 offset과 scroll-margin이 중복 적용되지 않게 확인한다. 모달·폼·슬라이더·3D 조작 안에서는 해당 입력이 스크롤에 가로채이지 않아야 한다. 움직임 감소에서는 즉시/네이티브 이동으로 전환한다.

## 포인터·드래그·모바일

목표값과 현재값을 분리한 damping/관성으로 포인터·회전을 연결한다. 프레임 수에 따라 속도가 바뀌지 않게 시간 차를 반영하고, 탭 복귀 시 큰 delta로 튀지 않게 한다. 직접 드래그 중 자동 모션이 입력과 싸우지 않도록 멈추고 놓은 뒤 자연스럽게 재개한다.

hover로 보여주는 핵심 정보는 키보드 focus와 탭에서도 접근 가능해야 한다. 모바일에서 단순히 모든 버튼을 숨기지 않는다. 긴 누름이 필요한 조작은 해당 control에 `user-select`, `-webkit-touch-callout`, `touch-action`과 pointer capture/cancel 처리를 검토한다. 일반 본문까지 선택을 금지하지 않는다. pointerup/cancel·창 blur에서 이동이 계속되는 고착 입력을 해제한다.

3D 이동처럼 별도 입력이 필요한 프로젝트는 조이스틱·가시적인 행동 버튼 등을 상황에 맞게 설계한다. 걷기/달리기/점프가 있다면 터치에서도 사용법과 현재 상태를 알 수 있어야 한다. 이 기능들을 일반 사이트에 추가하라는 뜻은 아니다.

## 상태·음향·미디어

진행 막대·슬라이더·재생 버튼은 실제 미디어 시간과 상태를 반영해야 한다. seek 후 재생, 일시정지, 반복, 음량 조절을 실제로 조작한다. 숫자만 바꾸거나 slider thumb만 움직이는 것을 동작 완료로 보지 않는다. 로딩 진행은 실제 준비 상태와 연출 시간을 구분한다.

음향이 있는 경험은 켜짐 상태와 음량 조절을 발견하기 쉽게 둔다. 브라우저의 사용자 입력 전 재생 제한을 고려해 첫 조작으로 시작하고, 실제 autoplay를 검증하지 않고 보장하지 않는다. 기존 사용자 음량 선택과 켜짐 선호를 보존한다.

## 연출이 보이는 성능

화면 밖·비활성 탭의 연속 모션을 멈추고, 재진입 시 상태를 부드럽게 복원한다. unmount/페이지 이탈 시 RAF·이벤트·observer·timeline·GPU 자원을 정리한다. 매 프레임 React 상태 갱신이나 반복 layout 측정이 필요한지 검토한다.

3D는 자산 크기·텍스처 해상도·GPU 업로드·셰이더 준비·조명/그림자 수·렌더 해상도·자원 재사용부터 진단한다. 무거운 준비 작업 사이에 브라우저가 로딩 화면을 그릴 시간을 준다. 처음 진입과 장면 전환을 둘 다 테스트하며 재진입 때 불필요한 재생성/다운로드를 확인한다. 저사양 장치용 대안을 두더라도 읽을 수 있는 UI와 작품의 핵심 형태를 유지한다.

`prefers-reduced-motion` 초기값과 실행 중 변경을 처리한다. 장식 루프·전진·parallax·긴 scrub은 정적 또는 짧은 상태 전환으로 바꾸고 콘텐츠·조작은 유지한다. JavaScript 또는 모션 초기화 실패로 본문 전체가 투명하게 남지 않게 한다.

자동 Motion QA의 `DEFERRED`/`UNSUPPORTED`는 미검증 상태다. 직접 입력, 실제 화면 변화, 반복 전환, 모바일 대안, 성능 관측을 별도로 남긴다. 단순 transform 변화나 “보기에 부드러움”만으로 모든 흐름을 PASS라고 보고하지 않는다.
