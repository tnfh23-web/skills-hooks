# 제작 과정을 보여주는 프로세스 페이지

소개·프로세스·포트폴리오 제작기를 요청받았을 때 읽는다. 여기서 프로세스는 **기획·디자인·제작 과정**이며 입장 전 순서대로 버튼을 누르는 안내 화면이 아니다.

## 내용과 실제 화면

페이지에서 다음 질문에 답할 수 있게 구성한다. 꼭 여섯 챕터나 이 순서를 강제하지는 않는다.

- 무엇을 만들었고 누구에게 어떤 경험을 주려 했는가?
- 왜 시작했고 해결할 문제는 무엇인가?
- 어떤 콘셉트·콘텐츠·서체·색·이미지 체계를 선택했는가?
- 화면/공간 구조와 주요 이용 흐름은 어떻게 이어지는가?
- 인터랙션은 무엇을 돕고 어떤 스택으로 구현했는가?
- 실제 화면에서 무엇을 확인하고 개선했으며 어떤 한계가 남았는가?

프로젝트의 분위기를 유지하되 메인 페이지의 콘텐츠를 그대로 반복하지 않는다. 전시 프로젝트의 차분한 공간과 기술 업데이트 아카이브의 정보 중심 분위기를 똑같은 색과 모티프로 처리하지 않는다. 긴 본문·시각 자료·구조도·실제 화면을 필요한 비중으로 배치한다.

런타임 화면을 설명하는 커버·썸네일·스크린샷은 **최신 구현을 직접 캡처**한다. 이전 배치나 생성 시안을 실제 결과처럼 남기지 않는다. 시안은 시안으로 표시한다. 작품 이름·설명·방 번호·프로젝트 기술 스택과 링크도 실제 콘텐츠와 일치해야 한다.

## 페이지 전반의 움직임

제목·본문·이미지·항목의 순차 등장과 반복 재진입을 설계한다. 처음 한 번의 hero fade로 끝내지 않는다. 이미지 선택·챕터 탐색·도표·사용 예시에는 내용에 맞는 클릭/focus 피드백을 준다. 기존 챕터와 레이아웃을 유지하라는 요청이면 움직임을 이유로 구조를 새로 만들지 않는다.

부드러운 스크롤과 챕터 앵커가 실제 scroll root에서 작동하는지 확인한다. 고정 헤더에 제목이 가려지지 않고 현재 챕터 표시가 맞아야 한다. 뒤로 가기·닫기·다시 열기에서 이벤트나 모션 인스턴스가 중복되지 않게 한다.

3D 로고가 프로젝트의 일부라면 자동 회전과 직접 드래그를 자연스럽게 연결할 수 있다. 입력 중 자동 회전을 쉬고 짧은 대기 뒤 감쇠하며 재개한다. 화면 밖·비활성 탭·움직임 감소에서는 자동 렌더/회전을 중지한다. 3D 로고가 없는 프로젝트에 이를 새로 강제하지 않는다.

## 포트폴리오와 공개 설명

관람/프로젝트와 프로세스는 각각 실제 주소로 연결한다. 같은 목록의 동등한 액션은 같은 정렬·간격·버튼 규칙을 사용한다. 데스크톱에서는 공간이 허용하면 한 줄로 배치하고 좁은 화면에서는 오버플로 없이 동일한 반응형 규칙을 적용한다.

바이브 코딩 README는 사용자 요청 시 “**바이브 코딩 프로젝트입니다.**”로 시작할 수 있다. 제작 계기·콘셉트·스택·핵심 기능·프로젝트/프로세스 링크를 중심으로 쓰며 “AI와 대화했다” 같은 협업 대화 경위를 설명의 중심으로 삼지 않는다. 상세 변경 로그와 내부 성능 숫자는 소개에 불필요하면 제외한다. 사용한 도구·생성 자산·외부 자산과 라이선스는 검증된 사실대로 밝힌다.
